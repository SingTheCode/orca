요청 범위와 결과

#요청결과
1GitHub에 Orca fork완료
2SpecFlow 기능 구현 제외반영 (SpecFlow 코드 이식 없음)
3omp를 기본 하네스로완료
4devx API Role 기본 세팅완료
6사내 Jira PAT 연동완료 (실제 PAT 연결은 미시험)
5, 7~10grill-me, 티켓 생성, 칸반, 동기화, Registry계획만 작성 (docs/specflow-fork-plan.html)

바뀐 내용

항목내용
앱 정체성번들 ID com.stablyai.orca → io.github.singthecode.orca. 업데이트 피드와 배포 대상은 SingTheCode/orca releases. 소유자 이름은 src/shared/release-channel.ts의 RELEASE_OWNER 한 곳에서 관리
omp 기본 에이전트새 프로필의 defaultTuiAgent를 'omp'로. omp가 없으면 기존 자동 선택으로 대체
devx Roleomp 실행 시 ~/.omp/agent/extensions/orca-devx-roles.ts 설치. devx-proxy(localhost:18888)를 provider로 등록하고, 사용자가 비워 둔 역할에만 프리셋 적용. 사용자 설정 파일은 수정하지 않음
사내 JiraJira 연결 창이 Self-hosted + 개인 액세스 토큰 + https://jira.sinc.co.kr로 미리 채워진 채 열림. 토큰만 붙여 넣으면 됨

검증

  • dev 앱에서 omp 실행 → DEVX-PONG devx/vertex_ai/claude-opus-5-5 응답 (omp 세션 기록으로 확인)
  • dev 앱 번들 ID io.github.singthecode.orca.dev, 기본 에이전트 omp, Jira 창 기본값 확인
  • 사내 Jira는 Server 9.12.6이며 Orca가 쓰는 REST 경로가 모두 존재
  • 테스트: 옛 피드 주소를 쓰던 업데이터 테스트 79건을 새 주소로 고친 뒤 통과. 시작 관련 테스트 1건은 대규모 병렬 실행에서만 실패하고 단독 실행에서는 통과
  • 타입체크: upstream에 원래 있던 오류 1건 외 신규 오류 없음

정정한 사항

  • 앱 ID 변경 범위: 처음엔 1번 범위 밖이라고 했지만, 검토표에서 1번의 작업으로 적어 둔 내용이었습니다. 이후 실제로 변경했습니다.
  • HTML 문서 커밋: upstream .gitignore가 docs/**를 무시해서, 앞서 "push했다"고 한 HTML 문서들이 실제로는 커밋되지 않았습니다. 강제 추가해 13155cac5f로 올렸습니다.
  • 기존 Orca와 병행 설치: "나란히 설치된다"는 안내는 틀렸습니다. 아래 위험 참고.

주의: 기존 Orca와 프로필 폴더 공유

번들 ID는 바꿨지만 사용자 데이터 폴더 ~/Library/Application Support/orca는 upstream Orca와 같습니다. 설정, 런타임 정보, Jira 토큰, 터미널 daemon 상태를 함께 씁니다.

상황결과
두 앱 동시 실행막힘. 단일 실행 잠금이 이 폴더 기준이라 두 번째 앱은 첫 번째로 넘기고 종료 (코드로 확인, 설치본 두 개로는 미시험)
번갈아 실행위험. daemon launchd 이름이 앱 ID로 시작해 fork와 upstream daemon이 같은 프로필에 둘 다 남을 수 있음
upstream 자동 업데이트위험. 더 새로운 스키마·프로토콜로 쓴 상태를 fork가 읽게 될 수 있음

현재 안내: fork로 옮길 때는 기존 Orca를 종료하고 Applications에서 지운 뒤 설치합니다.

배포 전 남은 일

  • Apple Developer ID 서명·공증, Windows 코드 서명. 서명된 릴리스가 없어 지금은 업데이트 확인 시 "새 버전 없음"
  • 번들 ID가 바뀌어 macOS 권한(손쉬운 사용, 화면 기록 등)은 다시 허용 필요
  • devx-proxy가 localhost:18888에서 실행 중이어야 Role 세팅이 동작

결정 필요

팀에서 기존 Orca와 fork를 함께 설치해 써야 하나요?

  • 함께 써야 한다면: 프로필 폴더 이름을 분리하는 작업을 따로 진행합니다. CLI와 daemon 경로 코드(metadata.ts, serve-bundle-coordination.ts, codex-home-paths.ts, logs-directory.ts)까지 함께 바꿔야 하고, 기존 사용자는 설정을 새로 잡아야 합니다.
  • fork가 Orca를 대체한다면: 지금 안내대로 충분합니다.
