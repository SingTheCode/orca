1차 구현 상세 (완료)

3. omp 기본 하네스

  • Orca는 이미 omp를 에이전트로 지원한다(src/shared/tui-agent-config.ts, 상태/프리필/타이틀 확장 자동 설치).
  • 신규 프로필의 기본값만 null(자동)에서 'omp'로 바꿨다. 기존 프로필에 저장된 선택은 유지된다.

4. devx Role 기본 세팅

  • Orca가 omp를 띄울 때 관리 확장 orca-devx-roles.ts를 함께 쓴다. 확장은 pi.registerProvider("devx")로 devx-proxy(http://localhost:18888/v1)를 등록하고 /v1/models로 모델 목록을 동적으로 받는다. 모델 한도·기능은 omp 번들 카탈로그에서 채워진다.
  • Role 프리셋은 사용자가 비워 둔 역할에만 런타임 override로 적용한다. 사용자의 modelRoles 값이 항상 우선이고, config.yml에는 기록하지 않는다.
Role프리셋
default / taskdevx/vertex_ai/claude-opus-5-5:medium
slow / plandevx/vertex_ai/claude-opus-5-5:xhigh
smol / tinydevx/azure_openai/gpt-6-luna:high
commitdevx/azure_openai/gpt-5.6-luna:high
visiondevx/azure_openai/gpt-6.1-sol:medium

사용자가 models.yml에 같은 이름의 devx provider를 직접 정의했다면 확장 등록이 그 위에 덮인다. 같은 프록시 주소를 가리키므로 동작 차이는 없다.

6. 사내 Jira PAT

  • Orca 기존 구현: JiraAuthType='server' → /rest/api/2, 이메일 없는 자격 증명은 Authorization: Bearer(src/main/jira/authenticated-request.ts). 토큰은 ~/.orca/jira-tokens/에 암호화 저장.
  • fork 변경: 연결 다이얼로그가 Self-hosted + PAT + https://jira.sinc.co.kr로 열린다. 사용자는 PAT만 붙여 넣는다. Cloud로 바꾸면 사내 URL은 비워지고, 사용자가 직접 입력한 URL은 유지된다.
  • 사내 Jira 확인: serverInfo = 9.12.6 Server. Orca가 쓰는 myself, search, project, createmeta/{project}/issuetypes, filter/favourite, agile/1.0/board 경로가 모두 존재한다(잘못된 토큰으로 호출 시 404가 아닌 401/400/익명 응답).

2차 계획

5. plan mode grill-me

  • omp는 plan 진입 시점 hook이 문서화돼 있지 않다. Orca에 Plan 실행 진입점을 두고, grill-me skill을 첫 프롬프트로 넣어 omp --plan 성격으로 실행한다.
  • 재사용 원본: SpecFlow grillMeInterviewGuide()(backend/services/agent_service.go:660-700), 응답 계약 INCOMPLETE / READY_TO_FINALIZE / COMPLETE(prompt_templates.go:137-186).

7. grill 결과 → Jira 티켓

  • grill 종료 시 Epic → Story/Task 목록을 JSON으로 산출하고 미리보기 후 일괄 생성.
  • 생성은 Orca 기존 orca jira create --project --type --title --body --fields-json와 project types/fields 사용. Epic Link는 사내 Jira의 custom field ID를 --fields-json으로 지정.

8. 칸반 연동

  • Orca Jira Tasks 보드뷰를 그대로 쓴다(Jira 상태 = 컬럼, 카드 이동 = transition).
  • 필요 시 워크트리 상태(todo / in-progress / in-review / completed)와 Jira 상태 매핑 설정을 추가.

9. 실시간 동기화

  • Orca → Jira: omp 확장 이벤트로 작업 시작 = In Progress, PR = In Review, 완료 = Done + 결과 코멘트. 대상은 워크트리에 연결된 이슈 키(orca reference).
  • Jira → Orca: 사내 webhook은 개인 PC에 도달하지 못하므로 보드가 열려 있을 때 30–60초 증분 polling(updated JQL).

10. devx Registry skill 설치·자동 업데이트

  • 실제 Registry 화면은 문서의 /api/v1/skills(404)가 아니라 /api/hub/skills를 호출한다. 목록, 상세(current_version_no, updated_at), /content, /download(zip)가 200. /versions는 작성자 전용(403).
  • 설치: zip을 ~/.omp/agent/skills/<slug>/(또는 프로젝트 .omp/skills/)에 원자적으로 교체. 설치 기록에 id와 current_version_no 저장.
  • 자동 업데이트: 주기적으로 상세를 조회해 버전 번호가 올라가면 재설치.
