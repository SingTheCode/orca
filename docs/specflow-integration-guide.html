SpecFlow 기능 Orca 통합 작업 설명서

2026-10-21 · Orca fork ~/dev/orca 브랜치 specflow-harness · SpecFlow 서버 ~/dev/spec_flow

Orca 왼쪽 사이드바에 SpecFlow 페이지를 추가했습니다. 저장소 하나를 SpecFlow 프로젝트에 연결하면 스펙, WBS, ERD, 코드 그래프 네 탭에서 기획부터 개발 검증까지 이어서 쓸 수 있습니다. 인터뷰는 SpecFlow 자체 채팅 대신 omp의 grill-me 스킬로 진행하고, 결과는 SpecFlow 서버가 PRD/TRD로 만듭니다. Jira 게시는 Orca에 이미 연결한 사내 Jira를 씁니다.

1. 전체 흐름

2. 시작하기

  1. SpecFlow 서버 실행: cd ~/dev/orca && scripts/specflow-local/up.sh --seed (DB, backend, devx LLM 설정). devx-proxy가 localhost:18888에서 실행 중이어야 LLM 기능이 동작합니다.
  2. Orca → 설정 → 통합 → 작업 공급자 → SpecFlow 카드에서 서버 URL, 이메일, 비밀번호를 넣고 연결합니다. 로컬 기본값은 http://localhost:8088입니다.
  3. 사이드바의 SpecFlow를 누르고, 현재 저장소를 기존 SpecFlow 프로젝트에 연결하거나 새로 만듭니다.
서버 주소는 설정값입니다. 나중에 공용 서버를 두면 URL만 바꾸면 됩니다. 팀 ID로 사용자를 묶는 관리 기능은 서버 쪽 별도 작업입니다.

3. 탭별 기능

탭할 수 있는 것
스펙 grill-me로 기획하기: 현재 워크트리에서 omp를 plan mode로 띄우고 /skill:grill-me로 인터뷰를 시작합니다. omp에는 이 프로젝트 전용 SpecFlow MCP가 붙습니다. 사용자가 공유된 이해를 확인하면 omp가 submit_grill_decisions로 결정 목록을 서버에 보내고, 서버가 PRD/TRD/QUESTIONS 새 버전을 만듭니다. 탭은 5초마다 확인하다가 새 버전이 생기면 알려 줍니다.
PRD/TRD/QUESTIONS 보기(Markdown), 편집 후 저장(새 버전 생성), 이력에서 두 버전 비교(diff), 추가 답변으로 다듬기.
WBSWBS 생성(기존 작업을 모두 지우므로 확인 후 진행), 우선순위·상태별 보기, 선후관계·일정·Jira 키 표시. 작업 상세에서 제목·설명·우선순위·일정 편집, 서버가 허용하는 상태로만 변경, 삭제, AI 하위 작업 제안 후 선택 저장. AI로 태스크 추가: 대화로 제안받고 골라서 생성. 다른 곳에서 바뀐 내용은 실시간(SSE)으로 반영됩니다.
WBS → JiraJira에 게시: 사이트·프로젝트·이슈 유형·Epic(선택)을 고르고, 아직 연결되지 않은 작업을 골라 순서대로 생성합니다. 성공한 작업에는 Jira 키가 기록되고, 실패한 작업은 사유를 보여 주고 나머지는 계속 진행합니다. 작업 상세에서 한 건만 게시할 수도 있습니다.
WBS → 검증작업 상세의 omp로 실행: omp가 SpecFlow MCP로 작업 지시서를 받아 구현·검증하고 submit_task_result로 결과를 올립니다. 아래에 검증 리포트(UNIT/E2E/SONARQUBE, PASS/FAIL, 로그) 목록이 표시됩니다.
ERD테이블·컬럼·관계를 캔버스에서 편집합니다. 테이블 이동, 추가·이름 변경·삭제, 컬럼 편집, 컬럼끼리 연결해 FK 지정, 관계 삭제. 저장하면 서버의 이름 규칙 경고를 보여 줍니다. AI로 생성, DDL 보기(복사 가능).
코드 그래프워크스페이스 업로드: 현재 워크스페이스를 zip으로 올려 분석합니다(.git, node_modules, 빌드 산출물, 숨김 파일, 1MB 넘는 파일 제외, 최대 20MB). 개요, 진입점, 핵심 파일, 검색, 호출자·피호출자, AI 설명, 에디터에서 해당 줄 열기. Go와 JavaScript/TypeScript만 분석합니다.

6. 알아 둘 점

  • grill-me 제출과 plan mode: 이전 프롬프트에서는 omp가 제출을 plan으로 만들고 Plan Review에서 멈췄습니다. 시작 프롬프트에 "plan mode에서 바로 MCP를 호출하고 plan으로 만들지 말 것"을 넣은 뒤 다시 실행했을 때는 승인 없이 바로 제출됐습니다. 모델 판단에 달린 동작이라, 혹시 Plan Review가 뜨면 Approve and execute를 누르면 됩니다.
  • 오래 걸리는 요청: PRD/TRD 생성 약 2분, 스펙 저장(AI 정제 포함) 최대 약 4~5분, WBS·ERD 생성 약 1분. 요청 제한 시간은 10분입니다.
  • WBS 다시 생성: 서버가 기존 작업을 모두 지웁니다(하위 작업, 상태, Jira 연결 포함).
  • 코드 그래프 재업로드: 매번 새 SpecFlow 프로젝트가 생깁니다. 서버의 재시도 API는 새 소스를 받지 않기 때문입니다. 이전 프로젝트는 서버에 남습니다.
  • Jira 생성 후 기록 실패: 이슈는 생겼는데 SpecFlow 기록이 실패하면 그 행에 표시만 하고 자동으로 다시 연결하지 않습니다.
  • MCP 키: 프로젝트마다 하나씩 ~/.orca/specflow-mcp/ 아래 0600 파일로 저장됩니다. 서버 URL이 바뀌면 새로 발급합니다.
  • 테스트 데이터: 로컬 서버의 orca-local-smoke 프로젝트에 검증 중 생긴 스펙 버전, 검증 리포트 1건, Jira 키 ORCA-101(가짜), 코드 그래프용 import 프로젝트가 남아 있습니다.
