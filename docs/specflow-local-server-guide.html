SpecFlow 로컬 서버와 통합 계획 작업 설명서

2026-10-20 · 저장소 ~/dev/orca (브랜치 specflow-harness, 커밋 7924f17d09) · 서버 소스 ~/dev/spec_flow

SpecFlow 기능 중 Orca에 없고 가치가 큰 8개를 Orca에 붙이기 위해 두 가지를 했습니다. 하나는 SpecFlow 서버를 개인 PC에 띄우고 LLM 호출을 devx-proxy로 연결한 것이고, 다른 하나는 그 서버를 쓰는 Orca 클라이언트를 어떻게 만들지 계획을 세운 것입니다. Orca 앱 코드는 아직 바꾸지 않았습니다.

1. 만든 것

파일역할
scripts/specflow-local/up.shDB 컨테이너와 SpecFlow backend를 띄웁니다. --seed를 붙이면 로컬 계정을 만들고 devx-proxy를 그 계정의 LLM 설정으로 등록합니다.
scripts/specflow-local/down.shbackend를 끄고 DB 컨테이너를 멈춥니다. 데이터는 남습니다.
docs/specflow-integration-plan.html8개 기능의 통합 구조, 단계별 일정, 위험, 결정 사항

스크립트는 SpecFlow 저장소를 수정하지 않도록 Orca 저장소에 두었습니다.

2. 로컬 서버 구성

구성주소설명
PostgreSQL 15localhost:5436docker 컨테이너 specflow_db. 기존 데이터 볼륨을 그대로 씁니다. 꺼져도 다시 켜지도록 unless-stopped 재시작 정책을 걸었습니다.

로컬 계정orca-local@specflow.test개발용 임의 계정. 비밀번호 기본값은 up.sh에 있고 SPECFLOW_LOCAL_PASSWORD로 바꿀 수 있습니다.
실행 파일·로그~/.local/state/specflow-local/specflow-backend(바이너리), backend.log, backend.pid

3. 사용 방법

시작

cd ~/dev/orca
scripts/specflow-local/up.sh --seed
  1. docker가 꺼져 있으면 OrbStack을 켜고 기다립니다.
  2. specflow_db를 띄우고 접속 가능해질 때까지 기다립니다.
  3. backend가 응답하지 않으면 Go로 빌드해 백그라운드로 실행합니다. 이미 떠 있으면 그대로 둡니다.
  4. --seed: 계정이 없으면 만들고, devx-proxy LLM 설정이 없을 때만 등록합니다. 여러 번 실행해도 중복되지 않습니다.

종료

scripts/specflow-local/down.sh

상태 확인

curl -s localhost:8088/health                      # {"service":"SpecFlow API Server","status":"OK"}
tail -f ~/.local/state/specflow-local/backend.log   # backend 로그
docker ps --filter name=specflow_db                 # DB 컨테이너

바꿀 수 있는 환경 변수

변수기본값
SPECFLOW_DIR~/dev/spec_flow
SPECFLOW_PORT8088
SPECFLOW_LOCAL_EMAIL / SPECFLOW_LOCAL_PASSWORD로컬 계정
SPECFLOW_DEVX_MODELvertex_ai/claude-sonnet-5-5
devx-proxy가 localhost:18888에서 실행 중이어야 LLM 기능(인터뷰, 명세, WBS, ERD 등)이 동작합니다. 서버만 켜고 devx-proxy가 꺼져 있으면 해당 요청이 실패합니다.

4. 확인한 기능

로컬 계정으로 테스트 프로젝트("점심 메뉴 투표 웹앱")를 만들어 실제 API를 호출했습니다.

기능API결과걸린 시간
AI 인터뷰POST /projects/:id/interview/evaluate권장안을 담은 질문 1개몇 초
PRD/TRD 생성POST /projects/:id/specs/generatePRD 7.5KB, TRD 13KB, QUESTIONS 1KB (버전 1)122초
WBS 생성POST /projects/:id/wbs작업 29개, 우선순위와 선후관계 포함56초
ERD + DDLPOST /projects/:id/schemas/generate, GET .../schemas/ddl테이블 설계와 PostgreSQL DDL54초
대화형 작업 생성POST /projects/:id/tasks/chat작업 제안 2건 (dialog_state: proposal)10초
코드 그래프POST /projects/import-source, code-analysis, code-graph/*Go 소스 분석, 노드 84 / 간선 139, 검색 동작몇 초
처음 PRD 생성이 500 오류로 실패했습니다. 코드 문제가 아니라 DB 컨테이너가 외부 종료 요청으로 정상 종료된 것이 원인이었습니다(Postgres 로그의 fast shutdown request). 재시작 정책을 건 뒤 다시 실행해 통과했습니다.

DB에 남은 테스트 데이터: 로컬 계정 1개, 프로젝트 2개(orca-local-smoke, jira-src-sample)와 그 산출물. 필요 없으면 SpecFlow 화면이나 DELETE /api/v1/projects/:id로 지울 수 있습니다.

5. 통합 계획 요약

자세한 내용은 docs/specflow-integration-plan.html에 있습니다.

방식

  • SpecFlow 서버의 프롬프트와 Go 로직을 그대로 쓰고, Orca에는 API를 부르는 화면만 만듭니다.
  • 로그인 토큰과 HTTP 요청은 Orca의 Jira 연동처럼 main 프로세스에서만 다루고, 계정 정보는 암호화해 저장합니다.
  • Jira 게시는 Orca에 이미 연결된 사내 Jira를 씁니다.
  • 작업 실행은 omp가 SpecFlow MCP 도구로 작업을 받고 결과를 올립니다.

단계

단계내용공수(추정)
P0 기반SpecFlow 클라이언트(로그인·토큰 갱신·SSE), 설정 카드, 저장소 ↔ 프로젝트 연결4~5일
P1 인터뷰·명세인터뷰 채팅, PRD/TRD 보기·편집, 버전 비교4~5일
P2 WBSWBS 생성·편집, 하위 작업, 대화형 작업 생성, 실시간 갱신4~6일
P3 Jira 게시미리보기 후 사내 Jira로 일괄 생성3~4일
P4 에이전트·검증omp에 SpecFlow MCP 연결, 검증 리포트 표시3~4일
P5 ERDmermaid로 보기, DDL2~3일
P6 코드 그래프워크트리 소스 분석, 검색·호출 관계·파일 열기4~5일

합계 약 24~32인일. P0 이후 P1, P2, P5, P6은 동시에 진행할 수 있습니다.

계획 중 확인한 제약

  • SpecFlow 작업 데이터에는 Jira 키 칸이 있지만 작업 수정 API가 그 값을 받지 않습니다. P3에서 서버 한 군데를 고쳐야 합니다.
  • 로그인 토큰은 10분, 갱신 토큰은 1시간이라 저장된 계정으로 자동 재로그인해야 합니다.
  • MCP 키(sf_mcp_)는 /api/v1/mcp/*에만 쓸 수 있어, Orca 화면은 로그인 토큰, omp는 MCP 키로 나눕니다.
  • 코드 그래프는 Go와 JS/TS만 분석하고, 업로드는 zip 20MB까지입니다.
  • Orca에는 reactflow가 없어 ERD·코드 그래프는 우선 mermaid로 보기만 제공합니다.

6. 결정 필요

  • 착수 순서: 기획부터 Jira까지 한 흐름으로 이어지는 P0 → P1 → P2 → P3을 권장합니다.
  • ERD 편집: 보기만으로 충분한지, 편집까지 필요한지. 편집이면 reactflow를 추가하고 약 3일이 더 듭니다.
  • 서버 운영: 계속 개인 PC에서 쓸지, 팀 공용 서버를 둘지. 클라이언트는 서버 URL만 바꾸면 되도록 만듭니다.
