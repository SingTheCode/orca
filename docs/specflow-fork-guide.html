Orca fork 작업 설명서

저장소 github.com/SingTheCode/orca · 브랜치 specflow-harness · 로컬 ~/dev/orca · 2026-10-19

Orca(stablyai/orca, MIT)를 fork해서 사내 개발 환경에 맞게 네 가지를 바꿨습니다. 앱 정체성을 fork 소유로 옮겼고, omp를 기본 에이전트로 지정했고, omp가 DevX 게이트웨이 모델을 역할별로 쓰도록 했고, 사내 Jira에 PAT 하나로 연결되게 했습니다. SpecFlow의 서버·DB·화면 코드는 옮기지 않았습니다. 나머지 기능(grill-me, 티켓 생성, 동기화, Registry)의 계획은 docs/specflow-fork-plan.html에 있습니다.

1. 앱 정체성 (fork 소유로 전환)

fork 빌드가 upstream 앱으로 인식되거나 upstream 업데이트에 덮이지 않도록 번들 ID와 업데이트 경로를 바꿨습니다.

항목이전이후
번들 ID (appId)com.stablyai.orcaio.github.singthecode.omdx
파생 IDcom.stablyai.orca.helper, .dev, .computer-use, .terminal.*, .serve같은 접미사로 io.github.singthecode.omdx.*
업데이트 피드github.com/stablyai/orca/releasesgithub.com/SingTheCode/orca/releases
electron-builder publishowner: 'stablyai'owner: 'SingTheCode'
  • 릴리스 저장소는 src/shared/release-channel.ts의 RELEASE_OWNER 한 곳에서 정합니다. 업데이터(updater-setup.ts, updater-release-feed.ts, updater-prerelease-feed.ts)와 agent-state-rules 다운로드가 모두 이 값을 씁니다.
  • 앱 이름(productName: 'Orca')과 사용자 데이터 경로(~/Library/Application Support/orca)는 그대로 뒀습니다. CLI와 daemon이 이 경로를 하드코딩해 찾기 때문에 바꾸면 기존 설정과 연결이 끊깁니다.
  • stablyai.orca-* 형태의 번들 플러그인 키는 플러그인 게시자 ID라 앱 정체성과 무관해서 바꾸지 않았습니다.
GitHub releases에 서명된 빌드를 올리기 전까지 자동 업데이트는 "새 버전 없음"으로 끝납니다. 사내 배포 전에 Apple Developer ID 서명·공증과 Windows 코드 서명을 설정해야 합니다. 번들 ID가 바뀌어 macOS 권한(손쉬운 사용, 화면 기록 등)은 새로 허용해야 합니다.
기존 Orca와 같이 쓰지 마세요. 번들 ID는 다르지만 사용자 데이터 폴더(~/Library/Application Support/orca)는 upstream Orca와 같습니다. 그래서 설정, 런타임 정보, Jira 토큰, 터미널 daemon 상태를 한 프로필로 공유합니다.
  • 동시에 실행은 되지 않습니다. Electron 단일 실행 잠금이 이 폴더 기준이라, 하나가 켜져 있으면 다른 쪽은 기존 창을 띄우고 종료됩니다.
  • 번갈아 실행하면 위험합니다. 터미널 daemon의 launchd 이름이 앱 ID로 시작해서(io.github.singthecode.omdx.terminal.* / com.stablyai.orca.terminal.*), 같은 프로필에 daemon이 두 개 남을 수 있습니다.
  • upstream Orca는 계속 자동 업데이트되므로, 더 새로운 상태 스키마나 daemon 프로토콜로 프로필을 쓴 뒤 fork가 그 데이터를 읽게 될 수 있습니다.
fork로 옮길 때는 기존 Orca를 종료하고 Applications에서 제거한 다음 fork를 설치하세요. 두 앱을 함께 써야 한다면 프로필 폴더 분리(CLI·daemon·codex 경로 포함)를 별도 작업으로 진행해야 합니다.

2. omp 기본 에이전트

src/shared/default-global-settings.ts에서 새 프로필의 defaultTuiAgent를 null(자동)에서 'omp'로 바꿨습니다.

  • 새 워크스페이스나 에이전트 탭을 열면 omp가 먼저 선택됩니다.
  • omp가 설치돼 있지 않으면 기존 자동 선택 순서(claude, codex …)로 넘어갑니다.
  • 이미 저장된 프로필의 선택은 바꾸지 않습니다. 기존 사용자는 설정 → 에이전트에서 직접 omp를 고르면 됩니다.

3. DevX Role 기본 세팅

Orca는 omp를 띄울 때 상태 표시용 확장을 ~/.omp/agent/extensions/에 설치합니다. 여기에 orca-devx-roles.ts를 추가했습니다(소스: src/main/pi/devx-roles-extension-source.ts).

동작

  1. omp에 devx provider를 등록합니다. 주소는 devx-proxy http://localhost:18888/v1입니다.
  2. 모델 목록은 프록시의 /v1/models에서 받고, 각 모델의 컨텍스트 크기와 기능은 omp 내장 카탈로그로 채웁니다.
  3. 사용자가 config.yml에서 지정하지 않은 역할에만 아래 프리셋을 적용합니다. 실행 중에만 적용하고 파일에는 쓰지 않습니다.
역할모델용도
default, taskdevx/vertex_ai/claude-opus-5-5:medium기본 대화, 서브에이전트
slow, plandevx/vertex_ai/claude-opus-5-5:xhigh깊은 분석, plan mode
smol, tinydevx/azure_openai/gpt-6-luna:high가벼운 작업
commitdevx/azure_openai/gpt-5.6-luna:high커밋 메시지
visiondevx/azure_openai/gpt-6.1-sol:medium이미지 이해

사용 조건

  • devx-proxy가 localhost:18888에서 실행 중이어야 합니다. 꺼져 있으면 devx 모델 목록이 비어 omp가 다른 provider를 찾습니다.
  • 역할을 바꾸고 싶으면 ~/.omp/agent/config.yml의 modelRoles에 적으면 됩니다. 사용자가 적은 값이 항상 우선합니다.
  • 프리셋을 쓰지 않으려면 확장 파일을 지우면 됩니다. Orca가 다음 omp 실행 때 다시 설치하므로, 영구히 끄려면 파일 첫 줄의 @orca-managed-pi-extension 표시를 지우세요(사용자 소유로 간주되어 덮어쓰지 않습니다).

4. 사내 Jira PAT 연결

Orca에는 원래 Jira Server/DC를 PAT(Bearer)로 붙는 기능이 있습니다. fork에서는 연결 창 기본값만 사내 환경에 맞췄습니다(src/renderer/src/components/jira-connect-dialog.tsx).

연결 방법

  1. 사내 Jira(https://jira.sinc.co.kr) → 프로필 → Personal Access Tokens에서 토큰을 만듭니다.
  2. Orca → 설정 → 작업 소스 → Jira 연결(이미 연결된 사이트가 있으면 Jira 사이트 추가)을 누릅니다.
  3. 창이 Self-hosted, 개인 액세스 토큰, 사이트 URL이 채워진 상태로 열립니다. 토큰만 붙여 넣고 연결합니다.
  • 토큰은 ~/.orca/jira-tokens/에 암호화되어 저장되고, 요청은 /rest/api/2에 Authorization: Bearer로 나갑니다.
  • Atlassian Cloud로 바꾸면 사내 URL은 비워지고, 직접 입력한 URL은 유지됩니다.
  • 연결 후에는 기존 Orca 기능을 그대로 씁니다: Jira 작업 목록·보드(상태별 컬럼, 카드 이동 시 상태 전환), orca jira CLI(검색, 생성, 상태 변경, 코멘트).

개발자용: 빌드와 실행

cd ~/dev/orca
pnpm install
pnpm dev                    # dev 앱 실행
pnpm run build:cli          # orca-dev CLI
node config/scripts/orca-dev.mjs agent launch --agent omp --prompt "hi" --json
pnpm run build:mac          # 로컬 macOS 빌드 (서명 없이)

upstream 변경을 받을 때는 git fetch upstream && git merge upstream/main 후, 새로 생긴 com.stablyai.orca 참조가 있는지 git grep com.stablyai.orca로 확인하세요.
